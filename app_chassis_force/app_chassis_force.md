## 0. 阶段划分

## 1. 坐标系与符号

- 底盘系：前 `x`、左 `y`、上 `z`；俯视逆时针 `w > 0`。
- `w` 是角速度，底盘系和世界系的 `w` 数值相同（平面运动）。
- 电机 ID：
  - `rudder_l_id = 2, rudder_r_id = 4`
  - `wheel_l_id = 1, wheel_r_id = 2`
- 轮 `i` 在底盘系的位置 `r_i = (x_i, y_i)`；舵角 `δ_i`（从 +x 逆时针）；轮半径 `r_w`。
- 轮滚动方向单位向量 `u_i = (cosδ_i, sinδ_i)`。
- 轮速 `v_i`、轮端纵向力 `f_i`、驱动转矩 `τ_i = r_w·f_i`，正方向均沿 `u_i`。
- 舵向电机输出力矩 `τ_δi`，由位置环 PID 计算。

上车前必须先确认并写死这些符号：

| 项                      | 需要确认                            |
| ----------------------- | ----------------------------------- |
| 左右轮位置 `(x_i, y_i)` | 与实车一致，否则 yaw 符号反         |
| 舵角零点与正方向        | 编码器零点、`δ>0` 对应逆时针        |
| 驱动轮正转方向          | 正力矩是否对应 `+u_i`               |
| 舵向电机正方向          | 正电流是否使 `δ` 增大               |
| IMU 安装方向            | 底盘 IMU 的 yaw 正方向与 `w>0` 一致 |
| 世界系/底盘系           | 平移命令用哪个系、yaw 命令用哪个系  |

## 2. 姿态观测（第一步：先只用 IMU 闭环）

### 2.1 第一步做什么

- 只使用 IMU 的 6 个量：三轴加速度、三轴角速度。
- 姿态估计给出 `roll/pitch/yaw`，yaw 环闭环；`w` 取 IMU 角速度或姿态微分。
- **不做**位置/速度闭环；IMU 单独无法长期观测速度（加速度计零偏会积分漂移）。
- 驱动轮只做前馈/开环力控，速度环等第二步有了轮速融合再闭合。

### 2.2 第二步：IMU + 轮速 KF

状态建议：

```text
x = [px, py, vx, vy, ψ, w, b_gz, b_ax, b_ay, (轮速尺度 s)]
```

- 预测：IMU 角速度/加速度；
- 量测：底盘正解的 `vx, vy, w` + 静止时的 ZUPT；
- 打滑：用 innovation/NIS、轮速-IMU 加速度一致性、左右轮一致性判；
- 输出：`v̂x, v̂y, ŵ, ψ̂`、`slip_flag`、逐轮滑移率估计、`NIS` 和置信度。

注意：底盘 IMU 和云台 IMU 是两个刚体。底盘 IMU 进底盘 KF；云台 IMU 只做云台姿态环。需要“整体姿态”时用关节角做坐标变换，不直接混估。

### 2.3 观测层优化点

- IMU 尽量装到车体中心、yaw 轴附近，减小杆臂；确有杆臂就做 `a = a_imu + α×r + ω×(ω×r)` 补偿。
- 轮速和 IMU 的时间戳必须对齐；CAN 反馈、IMU 采样、控制拍之间的固定延迟要标定，预测时向前推 1~2 拍。
- 打滑不要只看“轮速和 IMU 不一致”，要按轮分别算滑移率，并保留短时置信度，避免单拍误判。
- ZUPT：静止时用零速/零角速度量测抑制漂移。

## 3. 命令输入

不管什么模式，gimbal 都发底盘系的 `vx, vy, w`。

- 如果操作手给的是世界系命令，在入口处显式旋转到底盘系，不要在不同层混用坐标系。
- 命令整形：加速度/加加速度限制、死区、遥控失联归零。
- 整形后的命令同时给外环和舵向代价预测，保证“预测的命令”和“执行的命令”一致。

## 4. 闭环控制（第一步：直接分解力矩 + 舵向方向）

### 4.1 外环

第一步只闭环 yaw；速度用前馈/开环：

```text
F_des = m·a_cmd                // a_cmd 来自命令整形/前馈；先不加 RLS 摩擦
M_des = I_z·α_cmd + yaw 环输出
```

第二步有了 KF 速度后再加：

```text
e_v = [vx_cmd - v̂x, vy_cmd - v̂y]
a_cmd = a_ff + Kp_v·e_v + Ki_v·∫e_v
F_des = m·a_cmd + F_fric_ff
```

yaw 环（严格跟随）：

```text
e_ψ = wrap(ψ_cmd - ψ̂)
ω_ref = Kp_ψ·e_ψ
e_ω = ω_ref - ŵ
α_cmd = Kp_ω·e_ω + Ki_ω·∫e_ω
M_des = I_z·α_cmd + M_fric_ff
```

- 积分器只在未饱和时累加；功率限幅/力矩饱和时冻结或反算。
- 第一步 `F_fric_ff = M_fric_ff = 0`（没有 RLS）。

### 4.2 控制分配：整车 wrench → 2 个轮端力

先澄清一个容易混的点：

- `lib_chassis` 的逆解给的是每轮的 **（期望轮向 `d_i`，轮速大小 `|v_i|`）**，是纯几何量；
- 它**不给力矩**；
- 力控 app 需要自己把整车 `(Fx, Fy, Mz)` 分配成两个轮端纵向力 `f_i`，再换算成 `τ_i = r_w·f_i`；
- 舵向方向仍然可以复用同一个逆解给出的 `d_i`。

分配关系：

```text
[Fx]   [cosδ1            cosδ2          ] [f1]
[Fy] = [sinδ1            sinδ2          ] [f2]
[Mz]   [x1sinδ1-y1cosδ1  x2sinδ2-y2cosδ2]
```

记 `J(δ)` 为 3×2 矩阵，`W = diag(w_x, w_y, w_ψ)`，`R = diag(r_1, r_2)`：

```text
f = argmin (w_des - J·f)ᵀ W (w_des - J·f) + fᵀ R f
    s.t.  |f_i| ≤ f_i,max
```

第一步：

- 用当前舵角构造 `J`；
- 加权最小二乘 + 每轮力矩限幅；
- `W` 里把 `w_ψ` 取大（yaw 优先）；
- 某个轮饱和后整体缩放或重分配，不能一轮满、一轮不管；
- 先不做打滑/功率/摩擦项。

后续优化见 §6 的 C3~C8。

### 4.3 舵向方向

见 §7。核心：两个等价解 `(d, +) ≡ (d+180°, −)` 的推力完全相同，选哪个是**代价问题**，不是对错问题；必须两轮联合、看整车 twist，不能逐轮最短路径。

### 4.4 舵向位置环

```text
δ_err = wrap(δ_ref - δ_fb)
δ̇_ref = 速率/加加速度限制后的前馈
τ_δ^cmd = Kp_δ·δ_err + Ki_δ·∫δ_err + Kd_δ·d(δ_err)/dt
        + k_ff·δ̇_ref
        + τ_fric_ff(δ̇_fb)        // 第三步之后可选
```

- 误差必须 wrap 到 `[-π, π]`，否则过 ±180° 会绕大圈；
- `δ_ref` 不能是阶跃，先过连续角规划/速率限制；
- 舵向饱和时，驱动轮力矩要降额，避免“舵打不过去、轮子硬推”拖胎。

### 4.5 功率（第一步先不做）

```text
P_pred = Σ τ_i·ω_i + k1·Σ|ω_i| + k2·Στ_i² + k3
```

- 第一步只做保守的电流/力矩限幅；
- 第三步有实测功率和 RLS 功率后，再做功率限幅和按轮分配；
- 超限时按边际损耗分配：`∂P_i/∂τ_i = ω_i + 2k2τ_i`，优先给边际损耗低、不打滑的轮子；
- yaw 必须严格跟随时，功率不足优先保 yaw，缩平移；
- 限幅时冻结速度环/yaw 环积分，防止 windup。

### 4.6 执行层与安全

- 驱动轮：`τ_i^cmd = r_w·f_i + τ_fric_ff_i`（第一步 `τ_fric_ff=0`），转成电流 `i_q = τ/(Kt·gear)`。
- 舵向轮：位置 PID 输出电流/力矩。
- 分支切换时，舵角符号和驱动力矩符号必须**同拍生效**，力矩符号要斜坡，不能阶跃。
- 打滑：第二步之后 KF 降权轮速量测，速度环靠 IMU 短时撑住，RLS 冻结，指令降额。
- 失能：驱动 `τ=0`、舵向停止闭环（或 0 力矩），只读编码器；手动转舵后用编码器重新标定舵角零点。
- 过流、温度、功率、舵向限位、通信超时都要有降级/停机路径。

## 5. RLS 在线辨识（第一步：先不添加辨识）

### 5.1 摩擦 RLS（后续）

驱动轮：

```text
τ_wheel/r_w = m_eff·a + Fc·sign(v) + B·v + bias
回归量 φ = [a, sign(v), v, 1]
```

舵向轴/云台轴：

```text
τ = Fc + B·|ω|        // 或 Fc·sign(ω) + B·ω
```

- 先做舵向轴摩擦：只需力矩和角速度，不需要地面速度参考，最快见效。
- 驱动轮摩擦必须在**不打滑、有激励**时更新；用 KF 的 `v̂, â` 和 slip_flag 门控。
- 参数限幅、`P` 的迹/激励判据、innovation 限幅、冻结策略都要有。
- 输出只做前馈/诊断，不回灌 KF 量测噪声。

### 5.2 功率 RLS（后续）

```text
P = Σ τ·ω + k1·Σ|ω| + k2·Στ² + k3
```

- 必须有实测功率（裁判系统/超级电容）才做；没有就先跳过。
- 1~5 Hz 慢更新，只做功率预测、限幅、能耗诊断。
- 2027 只算轮向功率：按轮建模，打滑轮效率权重降低。

**第四点的优化部分（对应上表的 C3~C8、D1、D5）**：

1. **一个轮子打滑**（观测器给出）→ 降低该轮 `f_i,max`，把力往不打滑的轮子挪；但不能把另一个轮子压饱和；打滑轮需要承担 yaw 时，整体降额。
2. **摩擦力辨识、功率控制** → RLS 摩擦做前馈；2027 只算轮向功率，按边际损耗把功率分配给不打滑、效率高的轮子。
3. **舵向方向** → 4 候选整车 twist 代价，两轮联合，不用逐轮最短路径（§7）。

> 优先顺序建议：A1/D1/D2/D5 → B2/C1/C2 → A2/A3/B1 → C3/C4/C6 → E1/E2 → C8。
> 不要一次性把所有项都打开：每加一项都要有单独的日志和验收指标，否则无法判断是哪一项在起作用。

## 7. 不做整体规划控制时，舵向方向问题怎么解决

### 7.1 为什么可以单独解决

这里说的“不做整体规划控制”，是指**不把舵向、力分配、功率、滑移放进一个大 MPC 联合优化**。舵向方向仍然可以单独、稳定地解决，因为：

> **两个等价解 `(d, 正转) ≡ (d+180°, 反转)` 的推力完全相同。选哪个分支是几何歧义，不是控制模态的产物。**

位控和力控都一样；力控只是让预测器可以更准、控制集可以更大，不改变“必须两轮联合、看整车 twist”这个判据结构。`app_chassis/app_chassis.md` 已经在位控底盘上落地了这套方案（档 2），可以直接移植到力控 app。

### 7.2 问题本质

`LibChassisInverse` 给的是每轮的：

```text
(期望轮向 d_i, 轮速大小 |v_i|)
```

一个舵轮有两个等价解：

```text
(d_i, 正转)  ≡  (d_i + 180°, 反转)
```

两种解对整车推力完全相同，差别只有：

1. 舵轮要走多少角度、走多久；
2. 过渡期间推力方向偏多少、产生多少偏航；
3. 轮速/力矩符号不同，摩擦、功率、发热不同。

所以判据不能是“每个轮子走最短路径”，也不能是“哪个先到位选哪个”——这两条在 `app_chassis.md` 里都被日志证明会出问题：

- `|e| ≈ 90°` 时两种解等贵，逐轮最短路径会逐拍翻转（问题 1：抖动）；
- 两轮各自做决定，会出现“一轮翻、一轮不翻”，在 `y=±0.202` 上产生同向力偶（问题 2：自转）；
- “时间最短”在对称起步时四个候选的 `T` 完全相同，**时间是零信息量**；在不对称起步时甚至会主动选中自转的候选（`app_chassis.md` §2.2 表 2）。

### 7.3 最小可行方案：4 候选 + 短时域整车代价

#### 第一步：候选枚举

由命令 twist `(vx*, vy*, w*)` 和轮位置 `r_i` 算每轮接触点速度：

```text
v_i_vec = [vx* - w*·y_i, vy* + w*·x_i]
V_i = |v_i_vec|
d_i = atan2(v_i_vec.y, v_i_vec.x)
```

每轮两个分支：

```text
b_i = 0: 目标舵角 φ_i^c = d_i,        轮速/力矩符号 +
b_i = 1: 目标舵角 φ_i^c = d_i + 180°, 轮速/力矩符号 -
```

2 个轮 ⇒ **4 个候选组合**（`[0,0] [0,1] [1,0] [1,1]`）。

⚠ `d_i` 只依赖 `d_i mod 180°`，所以第一步即使只有 IMU、没有速度观测，也能用命令 twist 算出来。

#### 第二步：预测每个候选的过渡过程

对每个候选：

```text
φ_i(t): 从当前实测角 φ_i(0) 以 ω_max 走最短弧到 φ_i^c，到位后保持
s_i(t): V_i·cos(d_i - φ_i(t))        // 余弦律；两个分支恒等
ξ̂(t)  = LibChassisForward(φ_1(t), s_1(t), φ_2(t), s_2(t))
J(c)   = ∫₀ᵀ ‖ξ̂(t) - ξ*‖²_W dt
W      = diag(w_x, w_y, w_w)，w_w 取最大
T      = 候选里最慢一轮的到位时间（makespan）
```

要点：

- 用**正解**而不是各轮角差：正解里含“轮面不侧滑”约束，过渡期舵轮斜着推时，它会自动算出推力被 `cos` 投影并生成偏航；不需要手工分“平移/自旋”工况。
- 轮速用余弦律时，两个分支的轮速给定**完全相同**（`app_chassis.md` §2.1 的恒等式），所以决策量实际只剩“舵轮往哪边转”。
- 余弦**不能钳负**：钳到 0 会在翻转后半程产生无力死区。力控里同样不要给轮向做 `max(align, 0)`。
- 权重先归一化：线速度用 `max(|vx*|, |vy*|, |w*|·|y|)`，yaw 用 `|w*|`（为 0 时取 1 rad/s）。
- 预测器只需要一个物理量：**舵向最大角速度 `ω_max`**；取 `VMAX_MOTOR / STEER_GEAR_RATIO`（约 6.25 rad/s = 358°/s），不需要单独标定。轮向的加速度由余弦律决定，不需要标定；给定→实际的滞后约 11 ms，相对舵向过渡（100~300 ms）可忽略。
- 力控下驱动轮没有轮速闭环，但分支选择仍用上面的运动学预测；如果速度环足够快、轮子不滑，正解预测与位控版本等价。要让预测更准，可以把 RLS 的质量/摩擦/功率加进预测，但**不要改判据结构**。

#### 第三步：选最小 J

```text
best = argmin_c J(c)
```

三个工程细节（缺一不可）：

1. **平手保持**：枚举顺序把上一拍的分支排第一，并用严格 `<`。镜像对称工况下两个同分支候选的 J 会逐位相等（实测相对差 ≤ 7e-16），没有这条会逐拍翻转。
2. **1° 快路径**：两轮行程都在 1° 内 ⇒ J ≡ 0（J 非负，必为全局最优），不跑正解；稳态跟踪几乎全走这条路。
3. **可行性检查**：候选目标角超出软限位/线缆范围时置 `J = INFEASIBLE`；全部不可行就保持当前分支，并降低驱动转矩。

#### 第四步：执行

```text
φ_ref,i = d_i + 180°·b_i          // 连续角，不要 wrap 成阶跃
τ_i^cmd 的符号 = (-1)^{b_i}
```

- `φ_ref` 先过连续角规划/速率限制，再进位置 PID（`lib_traj_jerk` 或一阶/二阶限幅）；
- 分支切换时，驱动轮力矩符号**同时**切换，并做短斜坡；否则会出现“舵已翻、力矩没翻”的反向拖拽；
- 摩擦前馈 `Fc·sign(v)` 的符号也随分支翻转，不要漏；
- 第一步没有 RLS，摩擦前馈为 0，但符号切换逻辑要先写好。

### 7.4 如果连预测都不想跑：解析退化为先验

`app_chassis.md` 的收益-代价式可以当兜底：

```text
收益 B = (2|e| - 180°) / ω_max     // 反解相对正解省下的时间，仅 |e|>90° 为正
代价 C ≈ 两轮 e 跨 90° 时驱动力偶的冲量
        ≈ 2·|y|·|cos e|·|sin e|·F · (行程/ω_max)
翻 ⇔ B > C，且两轮同拍翻
```

- `|e| < 90°`：收益为负，不翻；
- `|e| = 90°`：收益为 0，**这正是抖动的来源**；换成交付代价判据后天然不翻；
- `|e| → 180°`：收益最大，掉头时应该翻。

这条规则是 4 候选 J 的退化形式，可以作为没有算力/没有正解时的兜底；但既然 `app_chassis` 已经实测证明了 4 候选 J 的正确性，优先移植它。

### 7.5 力控场景下额外可以融合的数据（可选，不改变主判据）

在几何 J 之上，可以逐项加小权重，用来打破近似平手：

| 数据                   | 加到代价里的方式 | 注意                       |
| ---------------------- | ---------------- | -------------------------- | ------------------------------- | ------------------ |
| RLS 摩擦 `Fc, B, bias` | `w_τ·            | τ_ff                       | `，反转分支的 `Fc·sign(v)` 不同 | 先影子模式确认参数 |
| RLS 功率 `k1,k2,k3`    | `w_P·P_pred`     | 只在平手附近起作用         |
| KF slip_flag/滑移率    | `w_slip·risk_i`  | 打滑时优先选低滑移风险分支 |
| 舵向电流/温度          | `w_I·            | I_δ                        | `、限位余量                     | 防止长期顶限位     |
| 舵向速率/行程          | `w_δ·            | Δδ                         | + w_δ̇·δ̇²`                       | 主判据已有，可强化 |
| 电机外特性             | `(τ/τ_max(ω))²`  | 避免选中后立刻饱和         |

原则：**几何 J 是主判据，摩擦/功率/滑移只用来打破近似平手**。全部无量纲化，逐项启用，并保留平手保持和切换代价；否则新增项会互相打架，重新引入抖动。

### 7.6 零速与纯旋转

- 纯旋转（`vx*=vy*=0, w*≠0`）：轮子切向速度 `ω × r_i`，方向明确；两个分支仍等价，按舵向行程和当前角选，静止时保持。
- 完全静止（命令全 0）：不要用 `atan2` 算方向；保持当前舵角。`app_chassis.md` 明确没有实现“静止时强制两轮对齐”——车不动时让舵轮白转一大圈，风险大于收益。
- 接近零速但仍有命令：加死区和最小速度阈值，低于阈值时保持上一拍分支；不要逐拍翻。

### 7.7 执行层必须配套

判据对了，执行层不对还是会抖：

1. **连续角规划**：`φ_ref` 不能是 ±180° 阶跃；用 `lib_traj_jerk` 或至少速率限制，否则位置 PID（kp 很大）会被反复踢。
2. **余弦不钳负**：轮速/力沿轮向的投影必须允许负值，否则翻转后半程无力。
3. **两轮同拍**：一个判据里两轮一起定，不要逐轮独立决定；`speed==0` 时保持（不强制对齐）。
4. **力矩符号斜坡**：分支翻转时驱动转矩过零再反向，不要阶跃。
5. **过渡期降额**：舵向大角度切换时，驱动转矩适当降低，避免拖胎和自转。

### 7.8 验证与验收

离线：

- `lib/lib_chassis/tools/demo_branch_cost.py`：候选/代价模型自检；
- `lib/lib_chassis/tools/verify_costsel.py`：复刻 C 侧判据 vs 2 ms 细格事后最优，看 regret；
- 210 个工况的验收标准：regret 中位/p95/最大 ≈ 1.000，粗格与细格 argmin 一致。

实车：

- `lib/lib_chassis/tools/analyze_vofa_rudder.py` 的 `[1] 分支分裂`、`[3] 两轮误差反向` 应为 0；
- 关注“单轮零推力段 > 0.05 s”是否消失（这是逐轮判据的典型失效形态）；
- 记录：`φ_ref, φ_actual, branch, J per candidate, chosen candidate, slip_flag, τ_i`；
- 指标：过渡期 yaw 误差、分支切换次数/秒、舵向到位时间、驱动电流峰值。

## 8. 落地顺序

1. **第一步：IMU 姿态/yaw 闭环**，先把坐标系、符号、失能零力矩和舵角标定做对。
2. **第一步：控制分配 + 舵向方向**：
   - 移植 `app_chassis.c` 的 `ChassisRudderCost / ChassisRudderDecide` 到力控 app；
   - `lib_chassis` 保持纯几何，不改内核；
   - 保留 4 候选、整车正解预测、平手保持、1° 快路径；
   - 加连续角规划和速率限制；
   - 加力矩符号斜坡和过渡期降额。
3. **第二步：IMU + 轮速 KF**，速度闭环、打滑检测、ZUPT。
4. **第三步：分配优化**，饱和重分配、打滑感知、功率限幅。
5. **第四步：RLS**，先舵向轴摩擦，再驱动轮摩擦；功率 RLS 需实测功率；先影子模式再接入。
6. **最后**再考虑 C8 的短时域联合优化（把分配和分支放进同一个代价），不要在第一步就上。
