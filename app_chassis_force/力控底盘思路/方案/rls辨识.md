### 输入输出

1. 轮向电机速度、电流；舵向电机速度、电流
2. 超级电容 / 裁判系统功率（功率 RLS 的 `y`，没有就不能在线辨识）

> **RLS 只是求解器**：`K=Pφ/(λ+φᵀPφ)`、`θ←θ+K(y−φᵀθ)`、`P←(P−KφᵀP)/λ`。
> 真正决定效果的是下面四件事：**模型结构、回归量 φ、观测量 y、采样门控**。
> 三份参考实现给的是两套模型：功率模型（RM2024 / YunQian）和摩擦模型（轮阻力拟合）。

---

## 1. 关 RLS：固定参数

先不辨识，直接写死一组参数，只做**预测**和**保守限幅**：

```text
驱动轮 / 舵向各一组：k1, k2, k3
轮向摩擦前馈：Fc = 0, B = 0
```

- 功率模型固定参数时仍能算 `P_cmd`，但参数不准就只当“软限幅”，不要拿它卡死功率。
- 摩擦前馈为 0 时，驱动轮速度环积分承担全部摩擦；舵向位置环没有积分，静息黏滑会保留。
- 第一步只跑 `lib_chassis` 的几何解算 + 舵向 4 候选代价，RLS 不参与。

## 2. 开 RLS：具体模型

### 2.1 功率模型

#### 形式 A：RM2024-PowerModule（推荐作为主模型）

```text
P = Σ_i τ_i·ω_i + k1·Σ_i|ω_i| + k2·Σ_i τ_i² + k3
```

| 项 | 含义 | 量纲 |
|---|---|---|
| `Σ τ_i ω_i` | 机械功率（可正可负，制动回馈为负） | W |
| `k1 Σ|ω_i|` | 摩擦/铁损，与转速成正比 | `k1`: W/(rad/s) = N·m |
| `k2 Σ τ_i²` | 铜损，`I²R` 折到力矩 | `k2`: W/(N·m)² |
| `k3` | 静态损耗（驱动、控制板、传感器） | W |

**回归量 / 观测量**：

```text
φ = [ Σ|ω_i|,  Στ_i² ]                 // 一般只在线辨识 k1、k2
y = P_measured − Στ_iω_i − k3
```

- `k3` 用“电机全部失能、底盘静止”时实测功率的平均值标定，**不要和 k1/k2 一起在线估**：三者容易共线。
- `k1`、`k2` 钳在 `≥ 1e-5`（RM2024 同款），防止符号翻负导致功率预测崩掉。
- 只在 `|P_measured| > 5 W`、功率源有效、电机在线时更新；实测功率先低通。
- 遗忘因子：`0.999 ~ 0.99999`。RM2024 用 `0.99999`（几乎不遗忘），YunQian 用 `0.999`（适应快但噪声大）。
- 更新率不要照抄 RM2024 的 1000 Hz；功率源通常 10~50 Hz，先低通再按 5~50 Hz 更新。

**分组**：

- 半舵底盘必须把**舵向组**和**驱动组**分开：
  `k1_steer, k2_steer` 与 `k1_drive, k2_drive`，`k3` 共用或分组固定。
- 原因：舵向零速保持时 `τω=0`，但电流不为 0，这部分铜损只能由 `k2_steer τ²` 捕捉；驱动组则主要是 `τω`。
- 同一组内的多个电机可以合并回归量为“求和”，参数相同；不同组参数不同。

**超限后的力矩解**（对每个电机）：

```text
k2·τ_i² + ω_i·τ_i + k1·|ω_i| + k3/n − P_alloc_i = 0
τ_i = ( −ω_i ± sqrt(ω_i² − 4k2(k1|ω_i| + k3/n − P_alloc_i)) ) / (2k2)
```

- 根号内为负 → 该电机在当前功率预算下无法维持，取顶点 `τ_i = −ω_i/(2k2)` 或直接降额。
- 符号按原 PID 输出方向取，不要跨零跳变。
- 功率分配权重可用“误差占比”和“功率占比”混合（RM2024 的 `errorConfidence`），或半舵的“舵向先拿 80%，驱动拿剩余”（YunQian）。

#### 形式 B：RM_YunQian half-wheel infantry

```text
P = K1·Στ_i² + K2·Σω_i² + Στ_iω_i + K3
```

- 与形式 A 的差别：用 `ω²` 而不是 `|ω|`，并把舵向/驱动两组合并成一个 4 参数 RLS：

```text
φ = [ Στ_steer², Σω_steer², Στ_drive², Σω_drive² ]
y = LPF(P_measured)          // 代码里 U 已包含 Στω + K3
```

- 默认参数：舵向 `K3=2.743 W`，驱动 `K3=3.057 W`；`K1/K2` 由 RLS 拟合。
- 功率分配：舵向组最多拿 80% 总功率，驱动组拿剩下的；组内按 PID 误差/功率占比分 `Membership`。
- **不要照抄它的负系数**：它拟合出的 `K2` 是负的（`-0.0018`、`-0.0086`），因为 `ω²` 项在局部工况里被用来吸收其他损耗；物理上耗散项应为非负，换成我们自己的模型时钳 `K1,K2 ≥ 0`。
- **不要照抄它的 LPF**：`Chassis_Power_Ctrl.c` 里 `LPF_ChassisPower.Alpha` 没有初始化，默认 0，等于没有滤波；我们要显式给 `alpha`（如 0.9）或改用时间常数。

#### 单位一致性（最容易错的地方）

- `τ` 和 `ω` 必须取**同一侧**：要么都用电机侧（`τ_m, ω_m`），要么都用输出侧（`τ_out=τ_m·gear, ω_out=ω_m/gear`）。
- `τ·ω` 两侧相等，但 `k1|ω|`、`k2τ²` **不相等**；拟合和应用必须同一侧。
- 输出侧力矩 = 电流 × `Kt` × 减速比；`ω` 用 rad/s，不要一边 RPM 一边 rad/s。
- 半舵：驱动轮减速比 1.0，舵向 M3508 减速比 8.0；两组分别换算。

### 2.2 摩擦模型

#### 形式 A：轮滚动阻力（轮阻力拟合参考）

双轮合并写法：

```text
(τ_L + τ_R) / R = m_eff·a + Fc·sign(v) + B·v + bias
```

逐轮写法（**半舵推荐**）：

```text
τ_i / R = m_eff_i·a_i + Fc_i·sign(v_i) + B_i·v_i + bias_i
```

| 参数 | 含义 | 量纲 |
|---|---|---|
| `m_eff` | 等效质量（含轮/转子惯量折算） | kg |
| `Fc` | 库仑滚阻 + 传动阻力 | N |
| `B` | 速度相关阻力（粘滞） | N·s/m |
| `bias` | 坡度/电流零偏/常值负载 | N |

**回归量 / 观测量**：

```text
φ = [ a, sign(v), v, 1 ]
y = τ/R                    // 双轮合并时 y=(τ_L+τ_R)/R
```

**前馈只用摩擦项**：

```text
F_fric,i = Fc_i + B_i·|v_i|
τ_ff,i   = sign(v_i) · F_fric,i · R / 2        // 双轮合并时除以 2
```

- **不补 `bias`**（坡度/零偏不是阻力，补了会把车往坡上推）。
- **不补 `m_eff·a`**：惯量前馈是另一项 `m_eff·a`，不要和摩擦混在一起；按当前建议连 `m_eff` 都不辨识。
- 速度死区 `0.04 m/s`，到 `0.15 m/s` 用 smoothstep 补满；零速附近不补，避免停车抖动。
- 变化率限制（如 `0.5 N·m/s`）、单轮上限（先 `0.2 N·m` 起步）、余量检查（`|基础力矩 + FF|` 不能顶到电流限幅）。
- 方向跟**实测轮速符号**，不跟 `setref`；`setref` 里有 `cos(align)` 和反向符号，含义不同。

**半舵为什么推荐逐轮**：

- 两个驱动轮可以独立转向；两轮不平行时，“双轮合并”的纵向方程不成立（载荷分配超静定、有侧滑/擦胎）。
- 逐轮模型写在轮子自己的滚动方向上：`v_i` = 轮速沿 `g_i`，`a_i = dv_i/dt`。
- `m_eff` 只在明显加减速时可辨识；日常准稳态下 `m_eff` 与 `bias` 容易互相抵消，还会把轮速差分噪声灌进 `Fc/B`。**建议 3 参数（Fc、B、bias），不辨识 m_eff**。

#### 形式 B：舵向轴 / 旋转关节摩擦

```text
τ_δ = Fc_δ·sign(ω_δ) + B_δ·|ω_δ| + bias_δ(δ)
```

- 回归量：`φ = [1, |ω_δ|]` 或 `[sign(ω_δ), |ω_δ|]`；观测 `y = τ_δ`。
- 参考实现的“整腿摆动摩擦”用**同一角度、正反两个方向配对取样**，取力矩差的一半，抵消重力/弹簧/惯量项；舵向轴是竖直轴，重力项小，但双向配对仍能抵消常值偏置（Kt 误差、电流零偏）。
- 舵向标定本来就让舵轮双向恒速扫描，是天然的辨识激励。
- 若舵轮重心相对舵轴有偏移，`bias_δ(δ)` 随舵角周期性变化；简单做法是双向配对消掉，或加 `A·cos(δ)+B·sin(δ)` 项（需要额外回归量）。
- 前馈：`τ_ff,δ = Fc_δ·sign(ω_δ) + B_δ·ω_δ`，同样做死区、限速率、余量检查。

#### 形式 C：最大静摩擦约束（不是 RLS）

```text
|F_i| ≤ μ·N_i
```

- YunQian 的写法：`F_max = μ·m/2`，再乘法向重力投影 `g_normal_mag`；超过就整体缩放。
- 这是**分配约束**，不是辨识；依赖质量、轮数、载荷分布、地面 μ，归 app / 分配器，不归 `lib_chassis`。
- 它和 RLS 的 `Fc` 不是一回事：`Fc` 是动摩擦阻力，`μN` 是轮胎附着上限。

### 2.3 采样门控与可辨识性

模型对了，门控不对照样辨识出假参数：

- 只用 RUN 状态、反馈新鲜、时间戳连续的数据；
- 轮速范围（如 `0.15~1.2 m/s`）、加速度范围（`|a| ≤ 1.0~1.5 m/s²`）、力矩范围；
- 半舵：舵角跟踪误差 ≤ 2~3°、舵速 ≤ 0.1 rad/s，转弯/擦胎段不采；
- 双轮速度差（合并模型必须；逐轮可选）；
- 换向瞬间、饱和段、打滑段丢弃；
- 前向/反向/加速/制动各 ≥ 50 个样本、总 ≥ 300；没有反向样本，`Fc` 和 `bias` 分不开；
- 回归量与观测量走**同一个低通**（参考实现 0.1 s），只滤一侧会把相位差做进参数里；
- 归一化回归量（`a/0.5`、`v/0.5`、`y/20`），避免 `P` 条件数爆炸；
- 激励判据：归一化 Gram 最小主元 ≥ 0.01；后验残差 RMS ≤ 2 N；参数落回物理区间；
- 数值失败**冻结**，不自动重试；下次上电/显式 Start 再来。

## 3. 模型和底盘类型相关吗？

**结论：公式本身与底盘类型无关，参数化、分组、门控和约束与底盘类型有关。**

| 项 | 是否随底盘类型变 | 说明 |
|---|---|---|
| 功率方程 `Στω + k1Σ|ω| + k2Στ² + k3` | **否** | 执行器级经验损耗模型；几轮、什么轮系都成立 |
| 参与求和的电机集合 | **是** | 半舵 2 驱动 + 2 舵向；麦轮 4 驱动；轮腿 2 驱动 + 2 腿 |
| 分组（舵向/驱动） | **是** | 半舵必须分组；四轮麦轮可一组 |
| `τ/ω` 取电机侧还是输出侧、减速比 | **是** | 半舵驱动 1.0、舵向 8.0；电机不同就不同 |
| 功率分配策略 | **是** | 半舵舵向优先 80%；麦轮按误差/功率占比；轮腿有解析分配 |
| 摩擦方程 `m_eff a + Fc sign(v) + Bv + bias` | **否** | 轮向一维方程；逐轮都成立 |
| 合并还是逐轮 | **是** | 半舵独立转向 → 逐轮；固定轮直行可合并 |
| 侧滑/擦胎/载荷转移 | **是** | 半舵转弯、麦轮横移会让一维模型失效，必须门控 |
| 舵向轴摩擦 | **仅舵轮** | `τ=Fc+B|ω|`；固定轮没有 |
| 最大静摩擦约束 `μN` | **是** | 质量、轮数、载荷分布、地面 |
| 参数数值 | **是** | 电机、减速箱、轮胎、地面、温度 |

所以可以做一个**通用的执行器级模型库**（输入一组 `{τ_i, ω_i, k1_i, k2_i}` 和 `k3`），但“哪些执行器、怎么分组、怎么分配、什么样本算有效”必须由底盘 app 给。

## 4. 可以复用 `lib_chassis` 吗？

**可以复用几何/运动学和名义力分配；不能指望它包含功率、摩擦、RLS、质量/μ、滑移和电机换算。**

当前 `lib_chassis` 提供：

| 能力 | 接口 | 力控里的用途 |
|---|---|---|
| 几何配置（轮数、位置、半径、类型） | `LibChassisConfig_s` / `LibChassisInit` | 半舵 2 舵轮 + 驱动轮 |
| 逆解：`ξ → (d_i, |v_i|)` | `LibChassisInverse` | 舵向目标方向、轮速大小 |
| 正解：`(舵角, 轮速) → ξ` | `LibChassisForward` | 里程计；舵向 4 候选的短时域预测 |
| 名义力分配：`W → (轮端 τ_i, 侧向力)` | `LibChassisAllocateTorque` | `(J⁺)ᵀW` 最小力范数解，作基线 |
| 雅可比与行信息 | `inst->jacobian`、`row_wheel`、`row_lateral`、`jtj_inv` | app 做加权/约束分配 |
| 最近的 ±180° 解 | `LibChassisSteerNearest180` | 无迟滞的几何工具；实时决策仍归 app |

需要注意的边界：

1. `LibChassisAllocateTorque` 输出的 `wheel_torque` 已经是**轮端力矩** `τ_i = R_i·f_i`，不要再乘半径；`lateral_force` 才是力。
2. 它是最小力范数、**无权重、无约束**的解；要 yaw 优先、功率感知、打滑感知、饱和重分配，必须在 app 层用 `jacobian` 做加权最小二乘/后处理。
3. `lateral_force` 换算成舵向电机力矩需要**主销偏移/擦胎半径**，`lib_chassis` 刻意不包含，归 app。
4. 它不做电机侧换算（Kt、减速比、电流限幅）、不做质量/μ/滑移、不做功率和摩擦模型。
5. 它不存跨帧状态；舵向换向的迟滞/代价选择归 app（`app_chassis` 已有的 4 候选方案）。

推荐的层次：

```text
lib_chassis        几何 + 正/逆解 + 名义力分配（纯计算）
lib_rls            通用 RLS 求解器（纯算法）
app_chassis_force  模型定义、门控、摩擦/功率前馈、加权/约束分配、功率限幅
```

如果以后别的底盘也要用功率/摩擦模型，再把“执行器级模型”抽成 `lib_chassis_energy` 或 `lib_actuator_model`；现在先放 app，避免过度抽象。

## 5. 半舵底盘的建议顺序

1. **第一步（关 RLS）**
   - `LibChassisInverse` 给 `d_i`、`|v_i|`；`LibChassisAllocateTorque` 给名义 `wheel_torque`；
   - 舵向方向用 4 候选 + `LibChassisForward` 预测；
   - 功率用固定 `k1/k2/k3` 只做预测/保守限幅；摩擦 FF = 0。

2. **第二步（开摩擦 RLS，先舵向）**
   - 舵向轴 `τ=Fc+B|ω|`：只需舵向电流/转速，不需要外部传感器；
   - 利用标定双向扫描采数据，离线拟合 `Fc/B`，先影子模式，再限速率接入；
   - 再上驱动轮逐轮 3 参数（Fc、B、bias），不辨识 `m_eff`。

3. **第三步（开功率 RLS）**
   - 前置条件：超级电容或裁判系统给实测功率；没有 `y` 就不要开；
   - 舵向/驱动分组，`k1_steer/k2_steer`、`k1_drive/k2_drive`，`k3` 静态标定；
   - 先固定参数验证预测误差，再开 RLS；先只做预测，最后才接限幅/分配。

## 6. 参考实现的坑（别照抄）

| 参考 | 可借鉴 | 坑 |
|---|---|---|
| RM2024-PowerModule | 功率模型、k1/k2 在线 + k3 静态、超限解二次方程、功率源切换、错误处理 | `RLS.hpp::validate()` 用 `lambda >= 0 || lambda <= 1`（恒真）；无 NaN/Inf 保护；1000 Hz 更新太快 |
| RM_YunQian | 舵/驱动分组 4 参数、舵向优先 80%、坡度投影 + 最大静摩擦约束 | `LPF_ChassisPower.Alpha` 未初始化（等于没滤波）；拟合出负 `K2`；旧 `Power_Control_Export` 是未编译副本；电流→力矩常数写死 |
| 轮阻力拟合 | 4 参数轮模型、φ/y 同滤波、20 ms 降采样、帧序号/断流门控、四工况计数、Gram 主元、RMS 判据、冻结策略、FF 死区/限速率/余量 | 腿式底盘的腿长/摆角门控不适用半舵；双轮合并假设不适用独立舵向；门限（2.8 N·m / 1.2 m/s）要按半舵重调 |

**最后一句**：`k1`（功率损耗系数，单位 N·m）不是 `Fc`（摩擦阻力，单位 N），两者不能互换；`Fc·sign(v)` 是动摩擦，启动突破力（静摩擦/Stribeck）要单独实测，别直接拿 RLS 的 `Fc` 当前馈。

## 7. 半舵功率 RLS 模块（预测 + 硬限幅）

实现：`app_chassis_force/app_chassis_power.{h,c}`；开关 `CHASSIS_POWER_PREDICT_ENABLE`
（预测/RLS）与 `CHASSIS_POWER_LIMIT_ENABLE`（限幅，见 §7.12）；
`app_cfg.h` 打开 `LIB_RLS_USED`。预测本身不参与分配、PID 或超电命令；
限幅只在驱动轮下发前裁 `τ_cmd`，不碰舵向、换向与力分配。

### 7.1 前提与边界

- 2027 规则舵向不计功率，超电 `chassis_power_w` 也已确认不含舵向 ⇒ 模型只含 2 个驱动轮。
- 舵向的 τ/ω/舵角完全不进入回归量、不进入 `y`、不进入 `k3`。
- 两个驱动轮共用一组 `k1/k2`：同型号同 Kt，且总功率只有一个观测量，逐轮 4 参数不可辨识。
- `τ/ω` 取电机侧（驱动减速比 1.0，电机侧 = 轮侧），app 正方向。

### 7.2 模型与归一化

```text
P = τ_L·ω_L + τ_R·ω_R + k1·(|ω_L| + |ω_R|) + k2·(τ_L² + τ_R²) + k3

S_w = 100 rad/s, S_t = 1 (N·m)², S_p = 10 W
φ0 = (|ω_L| + |ω_R|) / S_w
φ1 = (τ_L² + τ_R²)   / S_t
y  = (P_meas − P_mech − k3) / S_p
θ0 = k1·S_w/S_p = 10·k1,  θ1 = k2·S_t/S_p = 0.1·k2
```

归一化的目的：`lib_rls` 的 `param_min/param_max` 是所有维度共用一个区间。归一化后
`θ∈[0.01, 5]` 同时对应 `k1∈[0.001, 0.5] N·m`、`k2∈[0.1, 50] W/(N·m)²`，天然非负有界，
不需要再在 app 层逐参数钳位/回写。

`k3` 不参与在线辨识（与 k1/k2 低激励时严重共线），必须静态标定。

### 7.3 输入量

| 输入 | 来源 | 用途 |
|---|---|---|
| `ω_L, ω_R` | `g_chassis_feedback.wheel[].speed` | 回归量 φ0、P_mech、P_cmd |
| `τ_L, τ_R` | `g_chassis_feedback.wheel[].torque` | 回归量 φ1、P_mech、P_fb |
| `P_meas` | `g_super_cap_data.chassis_power_w` | y |
| `k3` | 静态标定常量 | y 与所有预测 |
| `τ_cmd,L/R` | `g_wheel_*_setref` | 仅 P_cmd |
| 轮时间戳/error、超电时间戳/状态、dt、RUN | `g_chassis_feedback` / `g_super_cap_data` / FSM | 门控 |

不需要：舵向量、IMU/车体速度/质量/滑移、母线 V/I、裁判系统。

### 7.4 门控与节奏

- RLS 更新周期 20 ms（50 Hz），且自上次更新后必须收到**新的超电帧**；
- RUN、两轮反馈新鲜（50 ms）、超电协议/DCDC/故障等级正常、超电帧新鲜（100 ms）；
  LK 广播反馈的 `echo` 是回显命令字而非错误码，轮向可用性只看时间戳/daemon；
- `|P_meas|>5 W` 且限制在 [-250, 700] W（避开编码饱和）；
- `|ω_L|+|ω_R| ≥ 2 rad/s`、`|τ_fb|` 与 `|τ_cmd| ≤ 4.0 N·m`；
- 换向后 100 ms 不更新；RUN 上升沿后暖机 300 ms；
- 输入 `isfinite` 先检查，坏帧直接跳过，避免把 RLS 永久冻死。

`φ0/φ1/P_mech` 用同一 RC=0.05 s 低通，与超电内部已低通的 `P_meas` 同相位口径；
**不要只滤一侧**，也不要对 `P_meas` 再滤一次。

### 7.5 输出

```text
P_fb_raw = P_mech_fb + k1·Σ|ω| + k2·Στ_fb² + k3
P_fb_lpf = 同一公式，三项都用低通后的值（与 P_meas 对账）
P_cmd    = Στ_cmd·ω + k1·Σ|ω| + k2·Στ_cmd² + k3   （τ_cmd 先钳 ±4.5 N·m）
```

`P_cmd` 用当前实测转速近似下一拍转速；`P_fb` 用于对账，`P_cmd` 为以后的前向限幅预留。
VOFA CH29~36 = `P_meas / P_fb_lpf / P_cmd / P_fb_raw / k1 / k2 / innovation / gate_mask`。
RLS 调参布局另有 CH9~14、CH24~26 输出回归量（见 §7.9）。

### 7.6 调用位置与非干涉

`app_chassis_force.c` 在超电 20 ms 发送块之后、VOFA 之前调用 `ChassisPowerUpdate()`；
此时 `g_wheel_*_setref` 已计算并下发，`g_super_cap_data` 刚刷新，后面只剩遥测。
模块不写 `g_wheel_*_setref`、`g_chassis_wrench`、`g_chassis_output`、超电命令中的任何一项。

### 7.7 k3 标定与验证

1. 驱动失能、底盘静止、DCDC 使能，记录 `chassis_power_w` ≥10 s，均值写入
   `CHASSIS_POWER_RLS_K3_W`；标准差应 <2 W。
   - **2026-10-22 已标定**：`ignore/rls_data/静止功耗.csv`，RUN 且 `MOTION` 不通过，
     90.7 s / 9069 帧，`P_meas` 均值 **4.03 W**、std 0.66 W、四分窗 4.19/4.03/3.94/3.95 W、
     线性趋势 −0.0045 W/s（可忽略），去 ±3σ 离群后 4.031 W ⇒ `CHASSIS_POWER_RLS_K3_W = 4.03f`。
     分析脚本：`scripts/chassis-power-calib/chassis_power_calib.py --static`。
2. `CHASSIS_POWER_RLS_UPDATE_ENABLE=0` 影子模式先验证符号与量级：前进取电为正、
   制动回馈为负；`P_fb_lpf` 与 `P_meas` 无系统偏置。
3. 开 RLS 后看 `k1/k2` 是否为正、不贴上下限、60 s 后波动 <10%；
   `innovation` 不应随速度/力矩呈现明显结构（有结构说明模型缺项或 k3 不对）。
4. 在线更新时 `P_fb` 天然贴近 `P_meas`（y 就是二者之差），**独立验证必须用固定参数或

5. 转向/舵向运动时 `P_meas` 不应因舵向动作明显变化；若 residual 与舵向电流相关，
   说明超电口径可能变了，需要重新确认 `chassis_power_w` 是否真的不含舵向。

### 7.8 机械项增益 g（已定量）

2026-10-22 三份日志的批量拟合（自由 g，`--fit` / `--abs-vs-sq`）：

| 日志 | n | g | k2 | k3 | RMS |
|---|---|---|---|---|---|
| 前段直线往返，后段原地旋转 | 5755 | 0.7360 | 13.76 | 3.84 | 1.37 W |
| 直线+旋转 | 3326 | 0.7233±0.0007 | 13.61 | 4.63 | 1.42 W |
| 随机运动 | 2037 | 0.7235±0.0017 | 13.95 | 3.58 | 2.82 W |

`--gain-scan` 检验 g 是否恒定（固定 k3/k2，分箱只拟合 g）：

| 分箱 | 直线+旋转 | 随机运动 |
|---|---|---|
| 低 / 中 / 高 转速 | 0.715 / 0.728 / 0.718 | 0.729 / 0.726 / 0.721 |
| 低 / 高 力矩 | 0.750 / 0.719 | 0.728 / 0.717 |
| 驱动 / 制动 | 0.724 / 0.711 | 0.724 / 0.696 |
| 前进 / 倒车 | 0.728 / 0.722 | 0.724 / 0.724 |
| 原地自旋 | 0.696 | 0.707 |

结论：**g 是恒定刻度（0.72~0.74），不是转速/方向相关的缺项**。前进与倒车完全对称，
排除符号/投影错误；自旋与制动略低 2~4%，量级在 k2 的拟合误差内。

把 g 强制为 1 时：k1 被顶到下限、k2 被抬到 16~18，预测 RMS 从 1.4 W 恶化到 9~24 W
⇒ **g 必须补**。

最可能的原因是 **LK 力矩常数（或 iq 刻度）偏大约 1/g ≈ 1.38 倍**，与多支战队的反馈一致。
注意模型自洽性：

- 机械项 `g·Στω` 与 `k2·Στ²` 的 τ 都取**上报值**（= Kt_assumed·i），所以只乘机械项即可；
- 铜损 `i²R = (τ/Kt_assumed)²R` 与真实 Kt 无关 ⇒ `k2` **不需要**跟着 g 变；
- 若反过来去改 LK 驱动的 `torque_constant`（0.28 → 0.202），则 τ 的刻度整体改变，
  `k2` 必须按 `1/g²` 重标（≈13.7 → 26.2），且控制链力矩一起变 ⇒ **不采用**。
  现方案只在功率模型里补偿：`CHASSIS_POWER_MECH_GAIN = 0.723f`。

### 7.10 |ω| 与 ω² 摩擦项对比

`--abs-vs-sq` 对同一份日志跑 6 种模型（g 固定 1 / 自由、摩擦项 |ω| / ω² / 无）。

2026-10-22 三份数据结论一致：**带自由 g 时，|ω| 与 ω² 的差别落在噪声内**：

| 日志 | g + \|ω\| + τ² | g + ω² + τ² | g + τ²（无摩擦项） |
|---|---|---|---|
| 直线往返+自旋 | RMS 1.34 W | 1.34 W | 1.37 W |
| 直线+旋转 | RMS 1.39 W | 1.39 W | 1.42 W |
| 随机运动 | RMS 2.82 W | 2.82 W | 2.82 W |

两项的系数都只有 0.00~0.02，且方向不稳定（随机运动里 \|ω\| 项甚至是负的）；
**去掉摩擦项几乎不掉精度**。真正决定精度的是 g（R² 0.95 → 0.998）。

所以：**摩擦项形式不重要，先定 g**；R² 从 0.90（g=1、无摩擦项）到 0.998 的提升
全部来自 g。新数据用 `--abs-vs-sq` 复算即可，不必在 STM 上跑两个 RLS。
保留 k1 只是为了给低速/铁损留一个自由度，在线落在下限属正常。

### 7.11 g 的物理归因（待台架确认）

g 有两个自洽的解释，对**功率预测**没有区别，但对将来的**功率限幅**有区别：

1. **Kt / iq 刻度偏大 1.38 倍**：上报 τ 偏大，机械功率按 0.723 缩放；铜损项因用上报 τ
   也自动吸收（k2 相当于物理值的 0.523 倍）。
2. **超电功率读数偏小 0.723 倍**：所有项（含 k3）都按比例缩小。

两个 10 分钟台架实验即可区分：

- **空载转速**：24 V 满占空比、空载，读编码器转速。
  实测 ≈805 rpm（datasheet）⇒ Kt 正确；≈1110 rpm（805/0.723）⇒ Kt 实际 ≈0.202。
- **相电阻**：断电后用万用表量两相间电阻 R_pp。
  R_pp ≈ 2.2 Ω ⇒ 与 `k2=13.9` 的「传感器刻度」解释一致；
  R_pp ≈ 4.2 Ω ⇒ 与「电流刻度偏大 1.38 倍」解释一致。

若是第 2 种（功率读数偏小），**将来用 `chassis_power_w` 做功率限幅会超功率 38%**，
必须改用裁判系统功率或对读数乘 1/g 修正。这也是目前不建议直接改 LK `torque_constant`
的另一个理由：改了也无法排除传感器口径问题，反而把控制链一起改掉。

### 7.12 功率限制（v1 硬限幅，固定 70 W）

**参考方案**（用户指定的 3 个项目）：

| 项目 | 限制方式 | 本车采用 |
|---|---|---|
| RM2024-PowerModule | 每电机 `P_i=τω+k1|ω|+k2τ²+k3/n`；回馈轮保持指令、负功率加回预算池；正功率轮按权重分预算；逐轮解 `k2τ²+ωτ+(k1|ω|+k3/n−budget)=0`，按指令符号取根，Δ<0 取顶点；另有 √能量 PD 环 | 模型结构、回馈记池、逐轮二次方程、k3/n |
| YunQian 半舵 | 同样的逐轮二次方程；舵向组先拿 80%；裁判上限扣 1 W 余量；非比赛固定 70 W | 70 W 固定档、1 W 余量、超电 DCDC 仍做最终兜底 |
| basic_framework_mc02 | 只有 `LimitChassisOutput()` 占位 | 不参考 |

本车没有逐轮速度设定值，RM2024 的“速度误差置信度”权重无法计算 ⇒ v1 只用**功率占比**
分配（等价于其 errorConfidence=0 分支）。**不做能量环/爆发、不做反馈修正。**

**宏（`app_chassis_force_def.h`）**

```c
#define CHASSIS_POWER_LIMIT_ENABLE 1
#define CHASSIS_POWER_LIMIT_SOURCE_FIXED 0
#define CHASSIS_POWER_LIMIT_SOURCE_RULE  1   // 比赛规则查表（预留，v1 返回固定值）
#define CHASSIS_POWER_LIMIT_SOURCE CHASSIS_POWER_LIMIT_SOURCE_FIXED

#define CHASSIS_POWER_LIMIT_FIXED_W 70.0f
#define CHASSIS_POWER_LIMIT_MARGIN_W 1.0f    // 生效上限 = 69 W
#define CHASSIS_POWER_LIMIT_MIN_W 5.0f       // k3≈4 W，再低物理不可达
#define CHASSIS_POWER_LIMIT_TAU_EPS_NM 0.02f // 小于它按“零指令轮”
```

生效上限 `limit_eff = max(来源值 − MARGIN, MIN_W)`。运行时动态值从
`ChassisPowerLimitInput_s.limit_w`（>0 覆盖）进；v1 传 0。

**分配流程**（`ChassisPowerLimitUpdate`，每拍 500 Hz，在驱动轮 `SetRef` 之前）：

1. 每轮 `P_i = g·τ_iω_i + k1|ω_i| + k2τ_i² + k3/2`，`P_total=ΣP_i`；
   `P_total <= limit_eff` 或 `enabled=0` ⇒ 原样直通（**不钳位**，关开关行为不变）。
2. 分类：
   - 零指令轮 `|τ_cmd|<eps`：保持 0，正功率从池中扣掉（`p_fixed`）；
   - 回馈轮 `P_i<=0`：保持指令，`−P_i` 加回池（`p_regen`）；
   - 其余正功率轮：进入分配，`drive_sum += P_i`。
3. `pool = limit_eff − Σ固定 + Σ回馈`；`pool<=0` ⇒ 驱动轮力矩置 0。
4. 先给每轮垫底 `p_min_i`（保持指令符号的可行域内的最小功率：顶点同号且不超指令幅值
   取顶点，否则 `τ=0` 的 `k1|ω|+k3/2`），剩余预算按 `P_i−p_min_i` 占比分配：

```text
pool >= Σp_min  → budget_i = p_min_i + (pool−Σp_min)·(P_i−p_min_i)/Σ(P_k−p_min_k)
pool <  Σp_min  → budget_i = p_min_i（尽力而为）
```

不垫底时，分到“比该轮最小功率还小”的预算会解出可行域外的根、只能输出 0，
反而固定多耗 `k1|ω|+k3/2`，导致总功率超上限（随机工况扫描最多超 ~10 W）。
垫底后 2 万组随机 τ/ω 扫描：无超限、无反号、无放大。
5. 逐轮解二次方程：

```text
b = g·ω, c0 = k1|ω| + k3/2
Δ = b² − 4k2(c0 − budget)
Δ<=0 → τ = −b/(2k2)（顶点，低速极小预算）
Δ> 0 → 在与 τ_cmd 同号的根里取离 τ_cmd 最近的；都不同号 ⇒ 0
```

选根用“同号最近根”而不是“按指令符号取根”：正常驱动象限两者一致；制动象限
（τ_cmd 与 ω 反号）按符号取根可能选到更远的根，同号最近根等价于留在指令所在分支。
限幅分支内再加：反号 ⇒ 0、`|τ|>|τ_cmd|` ⇒ 回退指令、钳 `±cmd_torque_limit_nm`。

**失败与边界**

- RLS 参数非有限或 `k2<0.1`、模块未初始化、输入非有限 ⇒ **直通（fail-open）**，
  由超电 70 W DCDC 兜底；不采用“坏帧停车”。
- `k1/k2` 直接读 RLS 当前 θ（与预测同一组）；限幅在预测更新之前调用也只用上一拍值，
  RLS 50 Hz，最坏滞后 20 ms。
- 逐轮独立缩放会改变 `τ_L/τ_R` 比例，理论上引入横摆；用 CH21~23 验证。

**遥测**（RLS 布局）：CH1 `limit_eff`、CH2 `P_before`、CH3 `P_after`、CH4 `scale_min`；
CH5/7 为限幅后 setref，CH31 (`P_cmd`) 应与 CH3 基本一致。

**验证**：`chassis_power_calib.py --limit-check` 输出超限比例、`scale_min` 分布、
`P_after` 是否 ≤ 上限、`P_after`/`P_cmd` 一致性、限幅段 `P_meas` 对账。
台架静态核对：一轮 `τ_cmd=0`、`ω=0`、`limit_eff=69` 时
`τ≈sqrt((69−4.03)/13.7)≈2.18 N·m`；两轮都给 4.5 时预算各半 ⇒ `τ≈1.54 N·m`。

**已知风险**：模型 RMS 1.4~2.9 W，70 W 减 1 W 余量仍可能瞬时超出；若超电
`chassis_power_w` 实际含舵向功率，限幅后 `P_meas` 会高于 `P_after`；g 的物理归因
（§7.11）未台架确认，若超电读数偏小则真实母线功率等比例偏大。v1 不做反馈修正。
