# 半舵底盘换向优化：问题描述与完整思路

本文件记录一件事：**把"舵轮选哪个 180° 等价解"从逐轮的最短路径判据，换成一个看整车的代价判据。**
纯解算内核 `lib_chassis` 不改（它保持纯几何、无状态），全部改动落在 app 决策层。

主线三步：**① 消变量（余弦律把轮向定死）→ ② 建判据（代价函数）→ ③ 定预测器（位控只需标一个量）**。
原"优化1（换向判据）"与"优化2（余弦）"是同一件事的两半，本文合并叙述。

---

## 一、优化问题描述

### 1.1 现象

**问题1（抖动）**：当舵向误差在 90 度左右跳变。例如当前几个控制周期内舵向位置 = 0，参考位置在
90.1 和 89.9 不断变化，解算根据最短路径走，就会让电机一下向左、一下向右，如果还有摩擦力，
会让 pid 积分和输出电流一直抵消。

**问题2（自转）**：如果舵向电机不管轮向电机的方向，每次就按照舵向的最短路径去走，会导致轮向
参考方向跳变。例如参考方向从向前到向右，当前舵向电机朝前偏左一点点（有点误差正常），舵向电机
就按照自己的最短路径向左转，然后让轮向反向。其实得不偿失，还会导致 w 旋转。

（现象描述：遥控方向从向前到向右，轮子也从向前到向右，都转过约 90°，但**转动方向可能不同**，
伴随轮向速度不为 0，一个轮子向前一个向后，车体自转。）

### 1.2 共同根因

内核 `LibChassisInverse` 给的是每轮的（**期望轮向 d_i，轮速大小 |v_i|**）——纯几何、无状态。
但一个舵轮有**两个等价解**：

```
(d, 正转)  ≡  (d + 180°, 反转)        推力 τ = φ + 180°·rev 完全相同
```

选哪个**不是对错问题，是代价问题**：两者推力一模一样，差别只有
① 舵轮行程 ② 行程中推力偏多少。内核是纯函数、不做这个选择（见 `lib_chassis.c` 的注释），
**选择落在 app**。现在的选法是"各轮按最短路径 + 15° 迟滞"，于是：

- **问题1**：|角差| ≈ 90° 时两种解等贵，判据正好卡在边界上，随噪声逐拍翻转
  ⇒ 目标舵角每拍跳 ±180°，位置环（kp=50）被反复踢，积分来回抵消；
- **问题2**：迟滞是**逐轮的状态**（`s_steer_reverse[i]`）。两轮上一拍的 rev 不同时，
  同一拍、同一个 d，两轮会做出**不同**的翻转决定 ⇒ 一轮翻一轮不翻 ⇒
  两个舵轮朝相反方向摆、驱动轮以相反符号运行 ⇒ 在 y=±0.202 上产生同向力偶 ⇒ **车体自转**。

⚠ 还有第二条独立触发路径：两轮角差一旦跨过 90°，**即使分支一致**驱动也会反号（cos 变号）：
e_L = −110°、e_R = −70° ⇒ 一轮反转一轮正转，**两个舵轮方向差 20° 就够**。
所以"平移时两轮必须指向同一物理方向"要三处一起保（见 §2.5）。

### 1.3 日志实证

44 s、19932 个 RUN 帧（`ignore/chassis_data/vofa+.csv`）：

- **t=16.686~16.718 那 17 拍**：两轮参考 ∓51.7°、驱动一正一反；同段两轮推力方向误差
  −52.3° / +52.1°（**符号相反**）⇒ y=±0.202 上力偶同向叠加，就是自转。
- **t=2.084~3.104 有 511 拍两轮差 27°**：进场时各锚各自实测，带着标定位置差进场。

检测工具：`lib/lib_chassis/tools/analyze_vofa_rudder.py` 的 `[1] 分支分裂` / `[3] 两轮误差反向`。

### 1.4 目标

判据要**看整车 twist**，而不是各轮比自己的角差——两个等价解对**单轮**永远平局，
只有放进整车才有高低。同时把"轮向"也一并纳入同一个判据，不做第二次独立决策。

## 二、完整思路

### 2.1 第一步：余弦律把"轮向"定死，于是两个解的差别只剩"舵轮往哪转"

app 现在的轮速给定量是

```
s_i = (−1)^b · V_i · cos(φ_target_i − φ_i)        φ_target_i = d_i − 180°·b,  b ∈ {0,1} 为分支
```

代入 b 的两种取值：

```
b = 0:  s = +V·cos(d − φ)
b = 1:  s = −V·cos(d − 180° − φ) = +V·cos(d − φ)      ← 恒等
```

**⇒ 轮速给定与分支无关：`s_i(t) = V_i·cos(d_i − φ_i(t))`,两个分支完全相同。**
自证：`tools/demo_branch_cost.py --check`（实测最大差 3.3e-16）。

两条推论：

1. **轮向完全按余弦优化给定，不需要为它单独做决策。** 过渡期它自己会从 +V 扫到 −V、
   过零、再反向——这正是"翻转"应该有的样子。原"优化2"到此并入主线，不再是独立优化。
2. **"选解" = "选舵轮往哪边转"。** 决策量从二维（舵角目标 + 驱动符号）塌缩成一维（转向方向），
   判据只需要比 φ(t) 的两条弧。

⚠ **余弦不能钳负**。现在代码里 `align = cos(ref − act); if (align < 0) align = 0;` 把 cos 钳在 ≥0。
钳了就不恒等了：翻转后半程（φ 越过 90° 之后）cos 本应翻负、轮子反向出力，钳 0 会变成一段
**无力死区**——舵轮还在转、轮子不出力，翻转被切成两段。⇒ 去掉钳负。
（1−cos³ 之类只是换一种"偏差怎么投影"的假设，不改变本节结构；要用等价的恒等式先成立再说。）

### 2.2 第二步：判据 = 代价函数

一句话：**把每个候选方案各自演一遍动画，看哪个过程中整车走偏得多。**

轮向在这里被自然地包含了——轮速按余弦律由 φ(t) 决定，它对整车 twist 的贡献由**正解**算出，
所以"整车姿态误差"里天然含了轮向分量。（用户表述：代价函数判断 2 种方案下**舵向的到位时间**
和**轮向速度分量导致的整车姿态误差**，就把轮向包含进去了。）

```
J(c) = ∫₀ᵀ ‖ ξ̂(t;c) − ξ* ‖²_W dt ,   W = diag(w_x, w_y, w_w)，w_w 最大

ξ̂(t;c) = LibChassisForward( 预测的各轮 (φ_i(t), s_i(t)) )
φ_i(t)  : 从当前实测角以 ω_max 走最短弧到候选目标（时间最优/砰-砰），到位后保持不变
s_i(t)  : V_i·cos(d_i − φ_i(t))          ← §2.1 的余弦优化，分支无关
T       : 候选里最慢一轮的到位时间（makespan），或固定上限
```

**为什么用正解**（关键）：正解里含"轮面不侧滑"约束，过渡期舵轮斜着推时，它会自动算出
"推力被 cos 投影 + 生成了偏航"，不用手工给工况分类。

三个要点：

1. **不用力控数据**。车体速度是运动学量——两轮"滚而不滑"时实际 twist 就是各轮速度的最小二乘解，
   而这正是 `LibChassisForward`。全程只需运动学，Kt/J/力矩/摩擦一个都不用。
   日志实证：t=16.686 那两拍实际轮速（一轮约 +0.61|v|、一轮约 −0.61|v|）喂正解得
   ξ̂ ≈ (0, 0, −3|v|)，而指令是平移（w* = 0）⇒ J 直接把"一个翻一个不翻"判死。
2. **权重只有三个数**，w_w 调大 = "最恨自转"。量纲不同（m/s vs rad/s）先用 |v*|、|w*| 归一化再加权。
3. **只需要排序正确，不需要绝对值准** ⇒ 预测模型粗糙没关系（见 §2.3），参数也不必精修。

#### ⚠ 为什么不能只比"哪个转到位更快"

直觉方案是"两种解谁先到位选谁"。**不行**，而且反例就在问题发生的那一点上。
以下两张表用 `tools/demo_branch_cost.py` 跑出（ω_max=358°/s，W=(1,1,3)）：

**表1：两轮对称起步（0°/0°），纯平移 +90°**

| 候选 | 行程 L/R | T | Yaw | J |
|---|---|---|---|---|
| L0 R0 同分支 | 90° / 90° | 251.4 ms | 0.000 | **0.127** |
| L0 R1 混分支 | 90° / 90° | **251.4 ms** | 0.396 | 2.400 |
| L1 R0 混分支 | 90° / 90° | **251.4 ms** | 0.396 | 2.400 |
| L1 R1 同分支 | 90° / 90° | 251.4 ms | 0.000 | **0.127** |

四个候选 **T 完全相同**（都是转 90°，只是反向）——时间是**零信息量**。能分开好坏的只有 Yaw。

**表2：两轮起步角 13°/−14°（复现日志里那个 27° 差），纯平移 +90°**

| 候选 | 行程 L/R | T | Yaw | J |
|---|---|---|---|---|
| L0 R0 同分支 | 77° / 104° | 290.5 ms | 0.107 | 0.360 |
| **L0 R1 混分支** | 77° / 76° | **215.1 ms ← 时间最短** | 0.378 | 2.333 ← 高出 6.7 倍 |
| L1 R0 混分支 | 103° / 104° | 290.5 ms | **0.420 ← 偏航最大** | 2.501 |
| L1 R1 同分支 | 103° / 76° | 287.7 ms | 0.105 | **0.350 ← 最优** |

**"哪个时间短选哪个"会主动挑中那个自转的候选**（L0R1），因为它确实更快（少转几十度），
代价是整段过渡一直拧着车。

⇒ 判据必须把"过渡期整车往哪偏"积进去。**时间并没有被丢掉**，它通过 **T 取候选自己的
makespan** 隐式进入：演得慢的候选积得多。新增的只有那三个权重。

顺带，`--sweep` 扫平移角也印证同一件事：两轮对称起步时，`|d| = 90°` 处同分支与混分支的
T **完全打平**（251.4 ms vs 251.4 ms），而 Yaw 是 0.000 vs 0.396——
**恰好在你出问题的那个工况上，时间判据退化成抛硬币**。这与收益式
`(2|e| − 180)/ω_max` 的结论一致：|e| = 90° 时收益为 0。

### 2.3 第三步：代价怎么预测（位控、没有力控数据）

预测器里**只有一个要标定的物理量：舵向实际角速度上界 ω_max**，其余全是几何。

- **舵向**：位控 + 速率受限 ⇒ 用"匀速斜坡"当模板。ω_max 从一次 90° 阶跃的实测最大斜率取，
  同时记下实际到位时间；两者对得上就说明斜坡模型够用。
  ⚠ 若实测明显拖尾（接近目标时位置环自动降速），就把斜坡换成"两段：先 ω_max 后收尾"，
  或直接拿**实测的到位时间曲线当模板**（查表插值）。代价比较只关心时间量级，粗糙无妨。
- **轮向**：**不需要标定轮向加速度。** 用余弦律时，轮速**给定**轨迹已被运动学决定
  （过渡中它自己从 +V 扫到 −V），那段"加速度"是模型算出来的，不是标定出来的。
  需要标的只有"给定 → 实际"的**滞后**：速度环穿越 ~14.6 Hz ⇒ τ ≈ 11 ms，而舵轮过渡
  145~360 ms，滞后占 3~8%，一阶近似可忽略。
  ⇒ 可选地把 `τ_w` 当一阶滞后补进去（或直接拿实测阶跃曲线当模板），不补也不影响排序。
- **命令 → 执行的 1~2 拍纯延迟**：要么 shift 进去，要么忽略（对候选排序是小量）。
- ⇒ **不需要力控/辨识数据**（Kt、J、摩擦都不用），用不上也就不必去测。

**将来若改力控**：判据结构一个字不用改，因为"选哪个分支"是**几何歧义**，不是控制模态的产物
——(d,+) 与 (d+180°,−) 产生的力完全相同，位控力控都一样，平局永远在。力控改变的是：

- **预测器变准**：可以用真实对象模型（J、Kt、摩擦）预测轨迹，排序更可信（但模型误差开始影响排序，
  现在这套几乎纯运动学，排序很鲁棒，这是优点）；
- **控制集变大**：多一个差动偏航力矩。控制量从"分支选择"扩成"分支 × 力矩剖面"，
  代价函数吸收它（加一项 `w_u·‖u‖²`），MPC 的标准扩展方式；
- 多一条治标路：不管分支、直接用力矩把偏航压掉——能行但贵，是压症状不是除根因。

### 2.4 其余约束（原"解决"第 1、3 条）

#### lib_chassis 传出的参数本就是整车的 (vx, vy, w)

内核给的是每轮的（期望轮向 d_i，轮速大小 |v_i|），两者都由**同一个** twist 导出
⇒ 两轮目标天然耦合，不是两个独立轴。所以决策层要拿整盘量来比：

- d_L 与 d_R 的差直接分辨工况：≈0 = 平移（两轮该指向同一物理方向），≈180 = 自旋；
- 代价要建在"两轮合成 twist vs 指令 twist"上，而不是各轮比自己的角差。
  ⚠ 内核是**纯几何、无状态**的：d_i 里没有任何"该走哪条路"的信息（±180 两个解等价），
  那部分只能由本层补——这也正是本优化存在的理由。

#### 收益与代价的解析式（档1 的退化形式，可作先验）

收益 = 反解相对正解省下的行程 / ω_max = `(2|e| − 180)/ω_max`：

- |e| < 90° → 负值，反解**更慢**，不翻；
- |e| = 90° → **收益为 0** ← 问题1 的抖动正好发生在这里；
- |e| → 180° → 收益最大（近乎掉头时舵轮几乎不用动，这才是反解存在的理由）。

代价 = 两轮 e 跨 90° 时驱动反号产生的力偶 ≈ `2|y|·|cos e|·|sin e|·F`，乘过渡时长（行程/ω_max）得冲量。
⇒ **收益 > 代价才翻，而且必须两轮同拍翻。**

⚠ 这条同时是**问题1 的正解**：90° 附近收益本来为零，所以不该"用迟滞把抖动压住"，
而该让**抖动区间自己失去收益**——判据换成"收益 > 代价"后 90° 附近天然不翻，
迟滞可以退出，两轮也不会各停在不同档上。上面的 `J` 就是它的完整版（解析式是它的先验/退化形式）。

### 2.5 三处一起保："平移时两轮必须指向同一物理方向"

- **决策**：两轮共用分支；`speed == 0` 时两轮保持**同一个**目标角（现在各保持各的）；
- **进场**：RUN 首拍各锚各自实测 ⇒ 两轮带着标定位置差进场（日志 t=2.084~3.104 有 511 拍两轮差 27°）；
- **过渡**：两轮角差跨 90° 时 cos 变号（见 §1.2 末），所以翻转要**同步**发生，不能一轮先到。

原则：**收益 > 代价才翻，而且必须两轮同拍翻。**

### 2.6 执行层配套

否则判据改了物理量还在跳：舵角参考走**连续角规划**（`lib_traj_jerk`，本 app 未接，
现在是位置环直接追阶跃）+ 轮速按余弦缩放且**不钳负**（见 §2.1）——翻转应表现为
"舵轮加速转到新分支 + 轮速过零"，而不是目标每拍跳 ±180° 把位置环（kp=50）踢飞。

### 2.7 命名与通用库

**名字有**：这个范式就是 **FCS-MPC**（Finite Control Set MPC，有限控制集模型预测控制）——
"枚举一个很小的离散候选集 → 各自预测一段 → 取代价最小者"，电机驱动/电力电子里就叫这个。
退化到 1 步、T = 一拍，就是**代价函数式切换判据**；只比"收益 − 代价"的正负号，
就是**带迟滞的效用判据**（现在这版迟滞是它的粗糙特例）。
另外"两轮都到位才算完成"的用时，学名是 **makespan**，不是求和。

**可以做成通用库，但别叫 fcsmpc、且现在不写**：

1. **命名即承诺**。FCS-MPC 作为一个*库*，等于承诺通用动力学接口 `ẋ=f(x,u)` + 时域 N +
   滚动优化 + 状态估计/反馈。这里没有状态估计、没有动力学（只有个速率限制），时域实质一段、
   无滚动反馈——是 FCS-MPC 的**退化特例**。挂这个名字，就会被逼着做一个通用模型 API
   （回调满天飞），为一个调用点造一个框架。
2. **可复用的内核很薄**：速率受限执行器的到达 + 加权误差积分 + 迟滞/回退。
   其余（候选怎么枚举、代价怎么算、权重怎么调）全是 app 知识。学术上 MPC 的难点是"模型"，
   **这里模型是 trivial 的，难点在候选集和代价**——那部分本来就没什么可复用。
3. 只有一个用户时设计接口 = 拿一个数据点外推。

建议形态（真要做时）`lib/lib_costsel/`（`LibCostSel*`，单体模块即可，将来出现"多步/连续版"再拆家族）：

```c
typedef struct { float from, to, rate, sign; } LibCostSelAxis_s; // 每轴：当前值/候选目标/速率/输出符号
typedef float (*LibCostSelEval)(const LibCostSelAxis_s *ax, uint8_t n, float t, void *ctx);
int8_t LibCostSelPick(const LibCostSelAxis_s *cand, uint8_t cand_num, uint8_t axis_num,
                      uint16_t steps, float dt, LibCostSelEval eval, void *ctx, uint8_t *best);
```

`eval` 由 app 给（本项目里 = 舵角斜坡 → 余弦给轮速 → 喂 LibChassisForward → 加权误差），
库只管枚举/积分/取最小；不依赖 bsp/drv，可 PC 单测 ⇒ 配套 `tools/verify_costsel.py`
（拿录制数据回放：给定当时的两轮角度与指令，看库选出的分支是否与事后最优一致）。

⚠ 别过度抽象：候选怎么枚举、误差怎么算这些 app 相关部分占大头，库只占三成。
落地顺序 **app 内先写纯函数（可单测）→ 稳定后再上提**；全舵版（4 轮 ⇒ 2⁴ = 16 个候选）
是第二个用户，等它出现才好验证抽象边界。

### 2.8 落地分档与验收

分三档落地，先止血再上模型：

- **档0**：两轮共用一个 rev（判据取两轮里收益较小者），消掉"一个翻一个不翻"；
- **档1**：判据从"最近路径"换成"收益 > 代价"（§2.4 的解析式），顺带退出迟滞；
- **档2**：上短时域预测（§2.2 的 `J`）；档1 的解析式退化成它的先验/退化形式。

**验收**：`lib/lib_chassis/tools/analyze_vofa_rudder.py` 的 `[1] 分支分裂` / `[3] 两轮误差反向`
改完应归零；`tools/demo_branch_cost.py` 用于离线核对判据选出的候选是否与事后最优一致。
